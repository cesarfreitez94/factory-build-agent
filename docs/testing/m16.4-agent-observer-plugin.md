# Testing - M16.4: OpenCode Agent Observer Plugin

## Requisitos Previos

- OpenCode instalado.
- Dependencias del proyecto instaladas (`pip install -e .[dev]`).
- Estar en un branch que incluya `.opencode/plugins/fba-agent-observer.ts`.

## Alcance de Validacion

El plugin `fba-agent-observer` agrega observabilidad local para los agentes del
meta-desarrollo del framework. Solo monitorea agentes declarados en `.opencode/agents`.
Los agentes plantilla en `templates/.opencode/agents` quedan fuera del indice, metricas
y reportes.

La V1 genera:

- `.factory/observability/agent-index.json`
- `.factory/observability/sessions/<session-id>.jsonl`
- `.factory/observability/reports/<session-id>.md`

## Pasos para Probar

### 1. Verificar indice de agentes observados

**Objetivo**: Confirmar que solo se indexan agentes del meta-desarrollo.

**Comando**:

```bash
opencode .
```

Dentro de OpenCode, inicia una sesion corta con cualquier prompt. Luego, en otra terminal:

```bash
test -f .factory/observability/agent-index.json
rg "framework-orchestrator|framework-builder|framework-registry" .factory/observability/agent-index.json
rg "templates/.opencode/agents" .factory/observability/agent-index.json
```

**Resultado esperado**:

```text
agent-index.json existe.
El indice contiene agentes de .opencode/agents.
El indice declara templates/.opencode/agents como directorio ignorado, pero no contiene
entradas de agentes plantilla como orchestrator, code-generator, tester_qa o planificador.
```

### 2. Probar medicion por agente

**Objetivo**: Confirmar que el reporte no agrupa todos los tokens en una sola metrica.

**Accion en OpenCode**:

Ejecuta una sesion que haga trabajar al `framework-orchestrator` y delegue a un subagente
observado, por ejemplo pidiendo un resumen de estado o una exploracion acotada del repo.

**Comando de verificacion**:

```bash
ls .factory/observability/reports
latest_report="$(ls -t .factory/observability/reports/*.md | head -n 1)"
sed -n '1,120p' "$latest_report"
```

**Resultado esperado**:

```text
El reporte contiene una seccion "Cost by Agent".
Cada agente observado aparece en su propia fila.
Los tokens/costo no se reparten proporcionalmente: si no hay atribucion confiable,
aparecen en "Unattributed".
```

### 3. Probar invocaciones entre agentes observados

**Objetivo**: Validar que el reporte muestre relaciones caller -> callee cuando OpenCode
expone partes `subtask` o `agent`.

**Comando de verificacion**:

```bash
latest_report="$(ls -t .factory/observability/reports/*.md | head -n 1)"
rg -n "Invocations|framework-orchestrator|framework-builder|framework-registry" "$latest_report"
```

**Resultado esperado**:

```text
Si la sesion tuvo delegacion observable, el reporte muestra una tabla de invocaciones.
Si OpenCode no expuso la relacion en eventos, el reporte indica que no detecto
invocaciones agente-a-agente observadas.
```

### 4. Probar trazabilidad de herramientas y archivos

**Objetivo**: Confirmar que el reporte clasifica actividad observable.

**Comando de verificacion**:

```bash
latest_report="$(ls -t .factory/observability/reports/*.md | head -n 1)"
rg -n "Tools by Agent|Files by Agent|Confirmed reads|Probable reads|Inferred reads|Edits" "$latest_report"
```

**Resultado esperado**:

```text
El reporte contiene herramientas por agente.
Las lecturas por herramienta read aparecen como confirmed.
Las rutas vistas por grep/glob/list aparecen como probable.
Las rutas inferidas desde bash aparecen como inferred.
```

### 5. Ejecutar tests automatizados

**Objetivo**: Validar que el plugin mantiene el alcance y defaults de privacidad.

**Comando**:

```bash
pytest tests/test_opencode_agent_observer_plugin.py -v
pytest
```

**Resultado esperado**:

```text
Todos los tests pasan.
```

## Troubleshooting

### No aparece `.factory/observability`

Reinicia OpenCode despues de cambiar el plugin. Los plugins locales se cargan al inicio.

### El costo aparece en `Unattributed`

Esto significa que OpenCode emitio tokens/costo sin una relacion confiable con un agente
observado. Es preferible dejarlo sin atribuir antes que contaminar la metrica de un agente.

### No aparecen agentes de `templates/.opencode/agents`

Es el comportamiento esperado. La V1 solo observa agentes del framework en `.opencode/agents`.
